# Lexos 中文演示指南

本文档服务于 Lexos 第一阶段目标：先可演示、再可运营、再可交付。当前演示的核心不是证明 Lexos 已经是完整律所 ERP，而是稳定展示一条可追踪、可审计、可结算的律所协作闭环。

## 1. 演示目标

### 核心叙事

Lexos 当前 demo 要讲清楚一件事：律所可以把“律师发起任务、律师承接任务、交付验收、客户确认、财务结算”放进同一个透明流程里，而不是依赖微信群、表格和人工追账。

### 本阶段必须让客户看到的价值

- 发起人可以把客户需求转成明确任务，并设置金额、交付说明和最低接单职级。
- 承办律师可以在任务大厅看到可抢任务，按职级条件接单并提交成果。
- 发起人可以验收承办成果，形成内部质量确认节点。
- 客户不需要完整账号，只通过安全访问 token、手机号和验证码进入客户确认页。
- 客户确认接收并评分后，系统自动生成结算记录。
- 财务可以查看并确认结算，关键动作会写入审计日志。
- 管理层可以通过总览、律师绩效、任务、结算、审计和参数页面理解后续运营抓手。

### 本阶段不主动承诺的能力

- 不承诺完整案卷系统、证据矩阵、文书正文管理或 AI 分析。
- 不承诺复杂虚拟团队分成、真实付款/退款打款、复杂基金审批或完整处分规则。
- 不承诺真实短信 MFA、客户独立账号体系或完整私有化安装器已经完成。
- 不把 Vercel Preview demo 等同于律所正式生产交付环境。

演示时建议把这些能力表述为“已预留方向、后续按运营和交付阶段推进”，避免把第一阶段 demo 讲成大而全系统。

### 真实 API 模式账号

真实 API 模式适合内部验收、联调和展示 Supabase 闭环，不建议在首次外部演示中临场依赖。真实模式下默认管理员为 `admin / 111111`，但当前线上管理员已完成首次改密，现场应使用演示负责人确认过的新密码。

真实 API 演示前建议：

- 提前确认 `NEXT_PUBLIC_DEMO_MODE=false`，并确认 Supabase 变量完整。
- 提前用管理员创建或复用 `source01`、`lawyer01`、`finance01`。
- 提前完成所有演示账号的首次改密，避免现场频繁改密打断叙事。
- 提前跑一次真实闭环 smoke，确认任务、客户确认和结算状态可达 `confirmed`。
- 不在客户现场展示 `.env.local`、service role key、Supabase 后台或任何真实密钥。

## 3. 标准演示脚本

建议演示时长控制在 20 到 30 分钟。第一次对外演示优先使用内存 demo 模式；如果客户明确关心数据库、权限和审计，再补充真实 API 模式说明。

### 演示前准备

1. 打开演示环境，确认首页可以访问。
2. 使用 `admin` 登录并完成首次改密，确认可进入“律所协作总览”。
3. 如需逐角色演示，提前把 `source01`、`lawyer01`、`finance01` 也完成首次改密。
4. 准备一条备用任务名称，例如“劳动争议仲裁材料审查”。
5. 准备一段成果说明，例如“已完成起诉状要点、证据目录和立案前风险提示”。
6. 确认客户确认页验证码为 `111111`；预置已验收任务可用 `LEXOS-DEMO-004 / 13800000000`，完整闭环演示可在验收 `LEXOS-DEMO-001` 后使用 `13900000000`。

### 开场：说明 Lexos 解决的问题

推荐话术：

“Lexos 第一阶段先不做大而全 ERP，而是先把律所最容易混乱的一条链路跑顺：发起人发单，承办律师承接，客户看到交付进度，财务按规则结算，管理层可以追踪每一步。”

展示“总览”页面，重点指向：

- 任务状态分布。
- 运营信号。
- 承办律师绩效。
- 最近任务扫描。
- 客户确认页入口区域。

### 第一段：管理员视角

使用 `admin` 登录。

演示顺序：

1. 进入“用户”，说明系统支持系统管理员、发起人、承办律师、财务等角色。
2. 进入“职级”，说明 L1A 至 L3C 职级和结算比例是当前简化结算规则的基础。
3. 进入“参数”，说明客户访问验证码、默认分页数量和显式结算锁定期已经接入真实业务规则。
4. 进入“审计”，说明关键操作会留下基础审计日志。

这一段不要展开复杂权限配置，重点让客户相信“系统不是单页面玩具，而是已有管理基础”。

### 第二段：发起人发单

切换到 `source01`。

演示顺序：

1. 进入“客户”，创建或展示“东辰科技有限公司”。
2. 进入“我的任务”，创建一条任务。
3. 推荐任务配置：
   - 任务名称：民商事一审代理材料准备。
   - 任务类型：诉讼任务。
   - 任务金额：12000 元。
   - 最低职级：L2A。
   - 截止时间：选择一个未来日期。
   - 交付说明：完成一审起诉材料、证据目录和立案前审查。
4. 展示任务详情中的流程节点、任务时间线、成果区和客户 token。
5. 展示任务详情中的里程碑完成度、下一步和交付记录，说明任务过程不是只看最终状态。

推荐话术：

“发起人不只是把事情派出去，而是把任务金额、接单门槛、交付标准和客户访问入口一起固化下来。后续谁接单、何时提交、何时验收、何时结算，都有状态可追。”

### 第三段：承办律师承接并提交成果

切换到 `lawyer01`。

演示顺序：

1. 进入“任务大厅”，展示开放任务。
2. 说明承办律师只能抢符合职级条件的任务。
3. 点击承接。
4. 进入“我的任务”，展开任务详情。
5. 提交成果说明和外部链接。

推荐成果说明：

```text
已完成起诉材料初稿、证据目录和立案风险提示，建议补充合同履行记录和付款凭证。
```

推荐外部链接：

```text
https://example.com/lexos-demo-deliverable
```

推荐话术：

“这里先不做文件上传，是为了第一阶段把交付状态和责任链跑通。当前成果支持文字说明和外部链接，后续可进入文件上传、证据矩阵和文书管理。”

### 第四段：发起人验收

切换回 `source01`。

演示顺序：

1. 进入“我的任务”。
2. 展开刚才的任务。
3. 查看承办律师提交的成果。
4. 点击验收。
5. 强调验收后，客户确认页才允许客户确认接收。

推荐话术：

“客户看到的是已经过内部验收的交付结果。这样既保护客户体验，也让律所内部质量控制有一个清晰节点。”

### 第五段：客户确认页确认

切换回 `admin` 或留在可看到总览的账号，进入“总览”页底部客户确认页区域。

演示顺序：

1. 输入访问 token。直接展示预置客户待确认任务时使用 `LEXOS-DEMO-004`；完整跑通“股权激励协议审查”时使用 `LEXOS-DEMO-001`。
2. 输入客户手机号。`LEXOS-DEMO-004` 对应 `13800000000`；`LEXOS-DEMO-001` 对应 `13900000000`。
3. 输入验证码。默认演示值为 `111111`，如已在参数页修改则使用当前参数值。
4. 点击“校验访问”。
5. 展示客户项目、交付内容和进度节点。
6. 输入评分，例如 `9`。
7. 输入评价，例如“交付清晰，响应及时。”
8. 点击“确认接收并评分”。

推荐话术：

“客户不需要被拉进内部系统，也不需要创建完整账号。第一阶段用 token、手机号和验证码提供轻量访问，先把交付确认和客户评分固化下来。”

### 第六段：财务确认结算

切换到 `finance01`。

演示顺序：

1. 进入“结算”。
2. 找到刚才任务生成的结算记录。
3. 说明当前结算规则：任务金额 × 承办律师职级比例 = 待结算金额。
4. 点击财务确认。
5. 展示结算状态变化。

推荐话术：

“第一阶段先做简化结算，让财务能看到金额、人员、任务和状态。锁定期、风控冻结、扣罚资金流向和资金台账已经有第一版；真实付款流水、退费打款和基金审批会放入后续运营阶段。”

### 收尾：回到审计和下一阶段

切换回 `admin`。

演示顺序：

1. 进入“审计”，展示登录、创建任务、承接、提交、验收、客户确认、财务确认等记录。
2. 进入“参数”，说明后续会把更多真实业务规则参数化。
3. 总结三阶段路线：
   - 先可演示：稳定讲清楚主闭环和客户确认页。
   - 再可运营：补强权限、统计、导出、评分和系统参数。
   - 再可交付：补生产安全、备份恢复、运维监控和私有化部署文档。

## 4. 客户确认页演示方法

### 推荐路径：工作台内演示

当前最稳的客户确认页演示方式是在 Lexos 工作台“总览”页底部完成。

内存 demo 模式下：

- 预置已验收任务 token：`LEXOS-DEMO-004`。
- 预置已验收任务手机号：`13800000000`。
- 完整闭环任务 token：`LEXOS-DEMO-001`，需要先由承办律师承接、提交，并由发起人验收。
- 完整闭环任务手机号：`13900000000`。
- 验证码：默认 `111111`，如已在参数页修改则使用当前参数值。
- 任务必须先进入“发起人已验收”状态，客户才能确认接收。

真实 API 模式下：

- token 在创建任务时显示一次，数据库只保存 token hash。
- 演示负责人必须提前记录本次任务 token。
- 使用任务对应客户手机号和当前客户访问验证码校验，默认值为 `111111`。
- 客户确认后会真实写入反馈并生成结算记录。

### 推荐讲解顺序

1. 先解释“客户不进后台，只看交付页面”。
2. 再展示 token、手机号、验证码三要素。
3. 校验通过后，展示任务标题、客户名称、交付说明、外部链接和进度节点。
4. 点击确认接收并评分。
5. 立刻切到结算页，展示客户确认带来的财务结果。

### 不建议的现场操作

- 不在客户面前打开 Supabase 表或展示密钥。
- 不临场新建真实短信服务或承诺当前已经接入真实短信。
- 不把客户确认页描述为客户完整门户；当前是安全链接式交付确认页面。
- 不在未验收任务上强行演示客户确认，否则页面会提示任务需要先验收。

## 5. 常见演示风险与处理

| 风险 | 现场表现 | 处理方式 |
| --- | --- | --- |
| 首次登录要求改密 | 登录后没有进入总览，而是进入改密页。 | 说明这是安全设计；演示前统一完成核心账号改密，或现场用 `11111111` 快速改密。 |
| 忘记当前演示密码 | 真实 API 模式无法登录。 | 切回内存 demo 模式或使用已确认的备用账号；不要现场重置数据库。 |
| 客户确认页校验失败 | token、手机号或验证码不正确。 | 直接展示用 `LEXOS-DEMO-004`、`13800000000`、`111111`；完整闭环用 `LEXOS-DEMO-001`、`13900000000`、`111111`。 |
| 客户无法确认接收 | 大屏提示任务需要先由发起人验收。 | 切回发起人账号完成验收，再回到客户确认页确认。 |
| 承办律师抢不了任务 | 任务最低职级高于承办律师职级，或任务已经被抢。 | 使用 `lawyer01` 抢 `股权激励协议审查`；`企业并购尽调清单复核` 是 L3A 门槛任务，用来展示职级限制。 |
| 结算记录没有出现 | 客户还未确认接收并评分，或真实 API 请求未完成。 | 回到客户确认页完成确认评分；等待页面成功提示后刷新结算页。 |
| 审计日志没有最新动作 | 页面数据未刷新或处于内存 demo 当前会话限制。 | 刷新审计页；对外演示只强调关键写操作已接入基础审计，不把日志数量作为核心卖点。 |
| Vercel Preview 数据被重置 | 内存 demo 不写真实数据库，刷新或重开后回到默认状态。 | 对外演示把这称为“安全演示环境”；真实数据验收另用 Supabase 模式。 |
| 真实 API 模式变慢或报错 | Supabase、网络或环境变量异常。 | 立即切换到内存 demo 完成业务讲解；真实 API 问题留到会后排查。 |
| 客户追问复杂风控/退费/基金 | 当前支持风控工单、裁决、冻结、扣罚流向锁定和资金台账第一版。 | 明确回答：第一阶段已经能锁定扣罚结果、生成内部资金流水并展示资金池余额；真实退费打款、银行流水、基金审批和复杂处分规则属于后续运营阶段。 |
| 客户追问私有化部署 | 当前 demo 是 Vercel Preview 或本地 demo。 | 说明长期目标是律所私有化或本地化部署，但交付阶段还需要确认部署形态、密钥管理、备份恢复、日志监控和升级方案。 |

## 6. 后续进入可运营阶段的检查清单

- [ ] 固定一套对外演示环境，明确是内存 demo 还是真实 API demo。
- [ ] 固定四个演示账号，并完成首次改密。
- [ ] 准备 2 到 3 套标准演示客户、任务、金额和成果话术。

- [ ] 每次对外演示前完成一次登录、发单、承接、验收、客户确认、结算的排练。

### 运营可用性

- [ ] 用户、客户、任务、结算和审计的服务端分页、搜索、筛选继续补齐排序和更细权限视图。
- [ ] 结算导出进入可用状态，满足财务对账和线下付款留痕。
- [ ] 审计日志导出从演示按钮升级为可运营报表。
- [x] 系统参数接入真实业务规则第一版：客户确认页验证码、默认分页数量和显式结算锁定期。
- [x] 客户与渠道基础统计进入总览页。
- [ ] 律师评分记录从客户评分扩展到内部评分和阶段性快照。

### 业务规则

- [ ] 明确承办律师承接资格、职级调整和权限变更的运营流程。

### 安全与交付前置

- [ ] 决定 Vercel Preview 是否继续使用内存 demo，或新建独立 Supabase demo 库。
- [ ] 真实 API demo 不复用生产库，service role key 不进入公开材料。
- [ ] 继续验证 anon 和 authenticated 不能直接访问内部表。
