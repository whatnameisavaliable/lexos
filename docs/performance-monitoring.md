# Lexos 性能监控 Runbook

## 目标与边界

本文件用于 Lexos 私有化或本地化交付后的性能监控口径。性能监控关注前端体验、核心 API 延迟、数据库查询、Storage 附件访问、运维脚本耗时和容量增长。

当前第一版只提供指标清单、阈值口径、证据要求和本地核对脚本，不采集真实用户数据，不写入数据库，不接入外部 APM，不做浏览器埋点，也不开发真实短信、新手保护期、新兵引流池、证据矩阵或 AI 辅助功能。

## 快速使用

执行：

```bash
npm run perf:check
```

该命令会读取 `.env.local`，输出性能监控核对清单。命令不会创建目录，不会写入文件，不会连接线上 Supabase，也不会上传外部监控平台。

可选环境变量：

```env
LEXOS_PERFORMANCE_OWNER=性能负责人
LEXOS_PERFORMANCE_REVIEW_INTERVAL_DAYS=30
LEXOS_PERFORMANCE_SAMPLE_RETENTION_DAYS=180
```

要求：

- 性能复核周期建议 30 天，最长不得超过 90 天。
- 性能样本保留期建议不少于 180 天，最低不得低于 90 天。
- 性能样本不得包含客户案件材料、附件正文、客户大屏 token 明文、手机号完整明文或密钥值。

## 核心指标

### 前端核心体验

范围：登录页、总览页、任务页、结算页、客户大屏。

目标：核心页面首屏可交互时间保持在可接受范围内，移动端客户大屏不出现明显卡顿。

预警：同一页面连续两次人工验收明显变慢，或客户大屏移动端加载超过 5 秒。

严重：客户大屏、登录页或结算页在验收环境不可用。

证据：浏览器人工验收记录、Preview smoke 结果、构建产物大小变化记录。

### 核心 API 延迟

范围：登录、任务列表、结算列表、客户大屏、附件签名下载。

目标：核心 API 响应稳定，分页查询不随数据增长明显退化。

预警：核心 API 多次超过 2 秒，或分页查询明显退化。

严重：核心 API 多次超过 5 秒或返回 5xx。

证据：server runtime log 摘要、`/api/health` 结果、真实 smoke 输出。

### 数据库查询与 RLS

范围：列表分页、搜索、排序、迁移后读取、RLS 验证。

目标：列表分页、搜索、排序和 RLS 验证稳定通过。

预警：分页查询出现超时、计数异常或手工 SQL 明显变慢。

严重：数据库连接失败、RLS 验证不通过或迁移后核心列表不可读。

证据：`npm run verify:rls` 输出、`supabase migration list` 输出、慢查询摘要。

### Storage 附件访问

范围：上传、内部签名下载、客户验证码授权下载、Storage 备份。

目标：交付附件上传和下载稳定可用，备份 manifest 对象数量可解释。

预警：单个附件下载偶发失败，或备份 manifest 对象数量异常。

严重：`lexos-deliverables` bucket 不可访问，或客户已验收附件无法下载。

证据：`storage-manifest.json`、附件下载验收记录、Storage 备份/恢复演练报告。

### 运维脚本耗时

范围：`backup:db`、`backup:storage`、`backup:rehearsal`、`private:check`、`launch:check`、`upgrade:check`。

目标：运维脚本能在维护窗口内完成。

预警：任一运维脚本耗时超过历史基线 2 倍。

严重：备份、恢复演练或上线核对脚本无法完成。

证据：脚本输出摘要、运维日志、错误日志。

### 容量与增长

范围：客户、任务、审计日志、资金流水、附件对象、备份体积。

目标：数据增长可解释，备份和对象存储容量在计划内。

预警：审计日志、附件对象或备份体积单周异常增长。

严重：磁盘、对象存储或数据库容量接近平台限制并影响写入。

证据：备份 manifest、审计报表、运维容量复核记录。

## 与错误日志和运维日志的关系

- 性能监控记录“是否变慢、容量是否异常、核心链路是否稳定”。
- 错误日志记录异常本身和处置线索。
- 运维日志记录发布、迁移、备份、恢复、异常处置和复盘结论。

性能预警可以引用错误日志和运维日志，但不要复制敏感明细。

## 当前限制

- 第一版不会接入 Web Vitals 自动采集。
- 第一版不会采集真实用户监控数据。
- 第一版不会写入数据库表、JSONL 或外部 APM。
- 第一版不会提供趋势图、告警路由或容量自动预测。
